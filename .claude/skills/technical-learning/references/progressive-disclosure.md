# Presentation：渐进披露、引用与回跳

## 何时读取

当写或修改 Markdown 文档涉及网址、论文、需要详解的术语、自测题答案，或用户要求“解释后补进文档”“答案放后面”时读取本文件。

## 核心原则

正文只保留理解主线所需的信息。会打断阅读但值得保留的细节放进文末专门区域，并从正文提供准确链接。

这是呈现规则，不是删减知识：正文负责连续理解，尾部负责按需深入。

## 正文与后置内容的判定标准

不要按“解释长不长”或“是不是用户追问”决定位置。先判断这段内容对后续阅读承担什么职责：

1. **前向依赖检查**：删掉它以后，目标读者还能否理解紧接着的句子、公式、图或步骤？不能，就必须在首次使用处保留正文解释。
2. **最小充分检查**：当前主线真正需要多少信息？正文给足可以继续推理的最小定义、因果和中间步骤，不把完整历史、全部证明或所有边界情况一并展开。
3. **打断成本检查**：细节虽有价值，但不影响当前推理，而且展开后会切断主线时，把完整版本后置；正文留下简短结论和准确链接。

| 内容职责 | 默认位置 | 处理方式 |
|---|---|---|
| 首次出现的符号、输入、输出、状态或非基础算子 | 正文 | 在第一次使用前后就地定义，不能要求读者先跳到文末才能读公式 |
| 后一步会直接使用的中间结果、关键因果或机制转折 | 正文 | 展示足以追踪下一步的过程，即使内容不短也不能整体后置 |
| 影响结论成立范围的关键限制或反例 | 正文至少一句 | 先防止正文形成错误理解，完整边界可链接到后置说明 |
| 概念需要一句定义，但完整推导或实现很长 | 正文 + 后置 | 正文提供最小充分解释，文末承载推导、扩展示例或实现细节 |
| 论文书目信息、历史沿革、补充消融、旁支比较 | 后置 | 正文只保留与当前结论直接相关的一句话和链接 |
| 自测答案、可选证明、罕见边界、查阅型术语详解 | 后置 | 放入对应专门区域，并提供往返链接 |

后置不是“所有解释统一放到最后”，正文也不是“用户问到什么就全部插在原地”。采用两层写法：**正文保证不断链，文末支持按需深挖**。一个细节即使只有一句，只要是后文的必要输入也应留在正文；一段内容即使很重要，只要正文已有足够摘要，其完整证明仍可后置。

## 四类对象

| 对象 | 正文写法 | 文末位置 |
|---|---|---|
| 普通网址 | `[说明文字](url)`，禁止裸 URL | 无 |
| 论文 | 首次出现链接到内部条目 | `## 参考文献` |
| 需详解术语 | 首次出现链接到内部条目 | `## 术语表` |
| 自测题答案 | 题目旁只放“参考答案” | `## 自测题参考答案` |

同一论文或术语通常只在首次出现处建立内部链接，后续使用普通文字，避免正文到处都是重复链接。

## 论文与术语

论文第一次出现时，正文只放简洁称呼：

```markdown
<a id="back-ref-example"></a>[原始论文](#ref-example)提出……
```

作者、全称、发表信息和外部链接放到文末：

```markdown
<a id="ref-example"></a>
### Example 原始论文

作者. *论文全称*. 年份. [论文页面](https://example.com)

[↩ 返回首次引用位置](#back-ref-example)
```

术语采用同样模式，但目标放进“术语表”：

```markdown
……使用<a id="back-term-example"></a>[示例术语](#term-example)。

<a id="term-example"></a>
### 示例术语

完整解释……

[↩ 返回首次出现位置](#back-term-example)
```

链接文字中不要嵌入 LaTeX。公式正常渲染，旁边使用纯文本链接。

## 自测题与答案分离

题目下面不直接展开答案，以免破坏主动回忆：

```markdown
1. 为什么需要 X？（<a id="back-answer-x"></a>[参考答案](#answer-x)）

<!-- 文末 -->
<a id="answer-x"></a>
### 1. 为什么需要 X

完整解释……

[↩ 返回题目](#back-answer-x)
```

用户后续追问形成的新解释继续更新文末答案，不把长讨论插回题目列表。

## 手动锚点

使用 HTML 手动锚点，避免依赖不同渲染器的标题 slug 规则：

- 论文：`ref-<短名>`，回跳为 `back-ref-<短名>`；
- 术语：`term-<短名>`，回跳为 `back-term-<短名>`；
- 答案：`answer-<短名>`，回跳为 `back-answer-<短名>`。

每个 `id` 必须唯一，每个内部链接必须有对应目标。长文档中的文末条目应提供回跳。

回跳不限于上表三类对象：**任何被链接的正文小节同样是跳转目标**（如表格/速查链到实现思路小节），同样要成对做——目标小节挂 `<a id="<前缀>-<短名>">`（前缀按对象起，如 `adapt-` 表示适配改动小节），引用处挂 `back-…` 锚点，小节末尾接 `[↩ 返回](#back-…)`。只做去程不做回程是半成品。多处引用同一目标时返回只指主引用处，其余靠阅读器后退——md 锚点单向，不带来路信息，无法按引用点分别跳回。

## 文末区顺序

按实际内容选用，不强制空章节。学习文档通常采用：

1. `## 术语表`
2. `## 自测题参考答案`
3. `## 参考文献`

普通网址不需要另建清单，直接使用描述性外链。

## 何时不要后置

- 读者理解当前段落不可缺少的定义、因果和中间步骤应留在正文。
- 短文档只有一处简短解释时可以就地写清，不必制造跳转。
- 内部代码引用、纯导航链接不属于术语或参考文献。
- 不要为了正文短而把所有解释都赶到文末，导致正文只剩结论。
- 不要等用户追问后机械地把整段回答插入正文；先按前向依赖和最小充分标准拆分，再决定哪些就地保留、哪些后置。

## 完成检查

- 无裸 URL，外链文字能说明目标。
- 论文首次引用与文末条目对应。
- 术语的简短上下文留在正文，扩展解释才后置。
- 每个公式和流程所需的输入定义都能在首次使用附近找到；正文没有依赖文末解释才能继续阅读。
- 长解释已经拆成“正文最小充分说明 + 后置扩展”，没有因过度就地展开而淹没主线。
- 自测题没有就地泄露答案。
- 锚点无重复、无缺失目标，往返链接有效。
- Markdown 代码围栏和数学围栏成对。
