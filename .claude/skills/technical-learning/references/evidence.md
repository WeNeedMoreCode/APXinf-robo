# Evidence：资料研究与证据核验

## 何时读取

当用户要求研究、查资料、核实事实、比较版本、引用来源，或主题具有时效性、陌生性和争议时读取本文件。

## 先界定问题

明确研究对象、时间边界、版本、预期深度和最终产物。不要把架构论文、后续产品版本、第三方实现和营销页面混成同一个对象。

先搜索仓库中已有笔记、文档和代码，整理：

- 已经覆盖的结论；
- 需要补充的空白；
- 可能过期或互相矛盾的内容；
- 用户已经接受或正在质疑的解释。

## 来源优先级

按问题类型优先使用最接近事实源头的材料：

1. 官方文档、规范、源码、技术报告、论文和模型卡；
2. 作者或维护者发布的说明、issue、变更记录；
3. 高质量复现、独立评测和技术分析；
4. 二手教程只用于寻找线索或比较讲解方式，不单独支撑关键结论。

搜索技术问题时优先引用原始资料。需要解释社区理解或实际踩坑时，再补充可靠的二手来源。

## 核验方法

- 检查发布日期、事件发生时间、适用版本和实验对象。
- 对关键数字、公式、配置和“首次/唯一/完全”等强结论回到原文核对。
- 多来源冲突时，不用多数投票；先判断它们是否讨论不同版本、阶段或指标。
- 论文自报 benchmark 只写成“作者报告”，不要自动推广成独立事实。
- 找不到直接证据时明确写“未找到公开证据”或“以下为推断”。

## 证据分层

写作时区分：

- **事实**：来源直接陈述、代码直接实现或实测直接观察到的内容；
- **推断**：由多个事实推导出的合理解释，但来源没有直接下结论；
- **类比**：帮助理解的教学模型，不等同于真实机制；
- **未知**：现有资料无法确认或不同来源尚未调和。

不要用顺畅叙事掩盖证据缺口。

## 研究输出

纯研究报告通常包含：

1. 结论摘要；
2. 已确认事实；
3. 争议、未知与时效边界；
4. 对用户问题的直接判断；
5. 逐条靠近相关主张的来源链接。

用户要求 cheatsheet 或速查时，改为“问题/场景 → 一句话结论 → 命令、配置或关键数据 → 来源/时效边界”，不保留报告式铺陈。

如果产物是学习笔记，将核验后的事实交给 Pedagogy 层重新组织，不要按搜索顺序堆资料。
