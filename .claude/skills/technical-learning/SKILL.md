# 技术研究与学习文档

把“找到资料、真正讲懂、整理成可复习文档”视为一条流水线，但只加载当前请求需要的层。

## 分层模型

```text
Evidence：资料是否可靠，哪些是事实、推断和时效性信息
    ↓
Pedagogy：读者怎样从已有知识自然走到新结论
    ↓
Presentation：正文与术语、引用、答案怎样分层呈现和往返
```

三层可以单独使用。不要因为 skill 被触发就强制搜索、重写整篇文档或添加练习题。

## 读取路由

| 用户目标或当前任务 | 必读文件 |
|---|---|
| 调研事实、论文、版本、最新变化，或为文档补证据 | `references/evidence.md` |
| 讲解概念、创建/重写教程或学习笔记、设计复习与自测 | `references/pedagogy.md` |
| 学习文档需要结构图、数据流、调用链或图中公式 | `references/pedagogy.md` + `references/diagramming.md` |
| 解释术语并补进文档、决定解释应就地还是后置，或把追问沉淀到文末答案 | `references/pedagogy.md` + `references/progressive-disclosure.md` |
| 只整理已有文档的论文、网址、术语链接或回跳 | `references/progressive-disclosure.md` |
| 从零创建有来源的完整技术学习文档 | 按上表依次读取三个文件，再读取 `templates/learning-note.md` |
| 只修改已有学习文档的局部解释 | `references/pedagogy.md`；若需判断正文/后置位置、处理引用或安排附注，再读渐进披露层 |
| 只整理已有文档的术语、链接或引用 | 只读渐进披露层；不要擅自扩大成研究任务 |

读取被路由到的文件时必须读完。未命中的 reference 不要加载，以控制上下文。

## 工作流程

1. **确认产物**：区分聊天解释、现有文档局部修改、完整学习笔记和纯研究报告。
2. **检查已有内容**：优先复用用户提供的上下文与仓库笔记，识别已经讲清和仍缺失的部分。
3. **按需核验**：事实可能变化、用户要求查资料、主题陌生或结论风险较高时执行证据层。
4. **建立学习路径**：先让读者知道对象是什么、位于系统哪里，再补齐可逐步追踪的运行过程，最后解释设计原因、取舍与边界；具体门禁见 Pedagogy 层。
5. **安排呈现层级**：正文保持连贯，详细术语、论文信息和自测答案按规则后置。
6. **验证结果**：检查事实与来源、解释完整性，并执行 Pedagogy 层规定的相邻章节冷读检查；存在图示时再执行 Diagramming 层的兼容与后备检查，最后检查锚点链接、Markdown 围栏和文件差异。

## 层间裁决

- 事实冲突时以证据层的可靠来源和适用对象为准，不能为叙事流畅修改事实。
- 教学层决定“按什么顺序讲”；呈现层只决定“细节放在哪里、怎样链接”，不重排知识依赖。
- 类比与推断必须服从证据边界，并明确哪些不是原文结论。
- 用户明确要求短答、不要联网、不要练习或答案就地展示时，按用户要求收缩对应层。
- 后续追问暴露正文缺少前提时，既更新文末答案，也补足正文中首次理解所需的铺垫。

## 默认产物策略

- 用户只提问：先直接回答，不自动写文件。
- 用户要求“记上、补进去、落盘”：修改当前相关文档，并保持现有结构和语气。
- 用户要求“研究后写一篇”：先核验证据，再创建学习路径，最后套用呈现规范。
- 用户只要研究结论或速查表：按证据层组织，不强行加入教程、自测或术语表。

## 完成标准

- 关键事实有可追溯依据，事实、推断与类比没有混写。
- 读者能画出主要对象的结构关系，并说明每个对象的输入、输出和状态。
- 读者能沿一个具体例子追踪核心过程，而不是只记住组件名称和设计理由。
- 读者能看出为什么从旧方案走到新方案，而不是只看到结论。
- 公式、符号与实现均在必要背景之后出现。
- 长解释不会打断正文，后置内容能准确跳转和返回。
- 复习要点与自测题服务于主动回忆，而不是装饰性收尾。
- 没有为使用模板而制造无关章节。
