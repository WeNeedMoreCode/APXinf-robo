# 候选枚举规则与动态策略

## 候选枚举规则

- 即使已经出现明显热点，也必须先枚举当前主链上的候选重计算子图和候选大图。
- 候选枚举应覆盖主链中可独立分析的前处理后重计算块、主干 / 编码阶段、状态读取阶段、融合阶段、状态写入 / 更新阶段、解码 / 预测阶段、后处理前重计算块等候选。
- 候选必须按功能分支标注归属；单样本、批量、流式、交互式、阶段式、带状态或 service 分支只要属于本次初步适配场景，就必须有候选、原始保留理由或排除证据。
- 首批候选应围绕高频交付场景形成最大连续主链大图，其他功能分支记录为后续批次、runtime variant、暂不支持或明确保留原始实现。
- 若多个候选只是在可选输入分支、输入构造方式或调用入口上不同，但替换点、主要重计算和输出消费者一致，应优先形成合并候选并尝试 OM；只有源码证明语义互斥，或导出 / ATC / 验证失败后重规划，才拆成多个候选。
- 主链重计算候选不得在未尝试或未形成重规划证据前直接归为 `fallback`；候选状态至少覆盖"本批尝试""后续批次尝试""需要补证后尝试""已确认非可图化控制 / 后处理"。
- 每个候选必须给出选择理由或暂缓原因、下一步 OM 尝试条件、下一批自动推进判断、输入 / 输出 shape 变化来源、影响图内数学的控制参数、是否可固定、可分档动态轴或可拆分语义分区、初始图侧主策略和证据。

## 动态策略选择

初始图侧主策略只做源码侧判断，单个 OM 只能选择一种：

| 策略 | 适用条件 |
|------|----------|
| `static` | 能确定 batch 和空间 / 序列尺寸时优先选择 |
| `dymbatch` | batch 动态 |
| `dymhw` | H/W 等空间尺寸动态 |
| `dymdims` | 有限多个维度组合可枚举 |
| `dymshape` | 动态已表达为图内 tensor shape / shape ops 且希望减少分档复杂度或无法稳定分档 |

关键原则：

- 代码支持可变不等于交付必须可变；若只有部分轴无法固定，应优先固定其余轴。
- 动态性若来自非 tensor 控制值，必须先捕获语义、来源和运行契约，判断能否转成图输入、固定部署契约、拆分语义分区或采用 runtime variant，再选择 `dymshape` 或其他动态策略。
